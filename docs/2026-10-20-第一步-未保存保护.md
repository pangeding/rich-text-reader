# 第一步：未保存保护

> 日期：2026-10-20
> 项目：Tauri 2 + React 19 + TypeScript + TipTap 3 Markdown 编辑器
> 范围：关闭窗口 / 打开文件前的未保存确认（三选项：保存 / 不保存 / 取消）
> 状态：已完成
> 关联文档：`2026-10-20-现状审查与优化方案.md`

## 1. 背景与目标

现状审查中，丢稿是最高风险：既没有快捷键，也没有任何未保存拦截。用户点击打开新文件或关闭窗口时，当前修改会被直接丢弃。

**目标**：在有未保存修改时，关闭窗口或打开文件前必须弹出确认，并且：

- 选「保存」：先落盘，成功后再继续关闭 / 打开；
- 选「不保存」：放弃修改，继续关闭 / 打开；
- 选「取消」：中止操作，窗口和内容保持不变。

## 2. 为什么作为第一步

1. 丢稿是当前最高风险，且触发路径最短（直接关窗口即可触发）。
2. 会引入 `onCloseRequested` 事件与确认交互，为后续快捷键、原生菜单、自动保存打下基础。
3. 不涉及编辑器内核与大范围重构，风险可控、可快速验收。

## 3. 实现范围

1. 关闭窗口时：若存在未保存修改，弹出三选项确认。
2. 打开文件前：若存在未保存修改，复用同一确认流程。
3. 选择「保存」时复用现有 `save_document`；当前无路径则走「另存为」。
4. 保存被取消或失败时，中止关闭 / 打开，不丢失内容。
5. 无修改时关闭窗口不做任何打扰。

不包含：快捷键、原子保存、图片去重、另存为图片迁移（属于后续 P0 项）。

## 4. 实现说明

### 4.1 确认对话框

新增 `src/components/ConfirmDialog.tsx`：

- 前端自绘，与现有 `LinkModal` 风格一致。
- 三个按钮：取消 / 不保存 / 保存，默认聚焦「保存」。
- 支持 `Esc` 取消；点击遮罩视为取消。
- 通过 `onChoice(choice)` 把 `"cancel" | "discard" | "save"` 交回调用方。

选择前端自绘而非系统原生 dialog 的原因：Tauri 原生 dialog 只支持两个按钮，无法同时提供「保存 / 不保存 / 取消」。

### 4.2 脏状态读取

`src/App.tsx` 新增：

- `dirtyRef`：与 `dirty` state 同步，保证关闭窗口的事件回调能读到最新值。
- `setDirtyState(value)`：统一更新 ref 与 state，替换原先散落的 `setDirty(...)` 调用。

### 4.3 保存结果可判断

`handleSave` 从 `Promise<void>` 改为 `Promise<boolean>`：

- 返回 `true`：保存成功；
- 返回 `false`：用户取消另存为，或保存失败（失败时通过 banner 提示）。

这样「保存后再关闭 / 打开」才能正确判断是否继续。

### 4.4 打开文件前确认

`handleOpen` 在调用 `open_document` 之前检查 `dirtyRef.current`：

- 用户取消 → 直接返回；
- 选择保存但保存未成功 → 中止打开；
- 选择不保存或保存成功 → 继续选择文件。
- `setContent` 用 `try/finally` 包裹 `suppressDirty`，避免异常时脏状态标记失真。

### 4.5 关闭窗口拦截

在 `useEffect` 中注册 `getCurrentWindow().onCloseRequested`：

1. 已处理过关闭（`closing`）或没有未保存修改 → 放行；
2. 有修改 → `event.preventDefault()`；
3. 已有确认框在显示 → 直接返回，避免重复弹窗覆盖 Promise resolver；
4. 等待用户选择：取消则返回；保存失败或取消保存则返回；
5. 确认可以关闭后调用 `appWindow.destroy()`。

`destroy()` 会绕过 `close-requested`，避免再次触发拦截。`core:window:default` 不包含销毁权限，因此在 `src-tauri/capabilities/default.json` 增加 `core:window:allow-destroy`。

### 4.6 样式

`src/App.css` 增加：

- `.modal-message`：确认文案样式；
- `.modal-actions button.danger`：「不保存」的警示色。

## 6. 验收标准

- [ ] 有未保存修改时关闭窗口，必定出现确认；
- [ ] 选择「取消」后窗口保持，内容不丢；
- [ ] 选择「不保存」后正常退出；
- [ ] 选择「保存」后文件落盘再退出；
- [ ] 无修改时关闭窗口不出现确认；
- [ ] 有未保存修改时点击「打开」，先确认再选文件；
- [ ] 打开确认中选择「取消」或保存被取消时，不弹出文件选择框。

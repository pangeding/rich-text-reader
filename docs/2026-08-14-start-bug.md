## 解决方案（2026-08-14）

### 根因

`tauri-plugin-dialog` 的 `blocking_pick_file()` / `blocking_save_file()` 返回 `Option<FilePath>`，而 `FilePath` 是一个枚举（定义于 `tauri-plugin-fs`，被 dialog 重导出）：

```rust
pub enum FilePath {
    Url(url::Url),   // file:// 或 content://
    Path(PathBuf),   // 普通本地路径
}
```

它**不是** `PathBuf`，不能直接用于 `std::fs` 操作和 `.display()` / `.file_name()`，因此产生 5 个编译错误。

### 修复方式

用 `FilePath` 的固有方法 **`into_path() -> Result<PathBuf>`**（`tauri-plugin-fs/src/file_path.rs:54`，对 `Url` 变体会尝试 `to_file_path()`），转换后再做文件操作。无需新增依赖。

### 修复后的关键代码（src-tauri/src/lib.rs）

```rust
// open_document
let Some(file) = app.dialog().file().add_filter("Markdown", &["md", "markdown", "txt"]).blocking_pick_file() else {
    return Err("cancelled".into());
};
let path = file.into_path().map_err(|e| e.to_string())?;
let content = std::fs::read_to_string(&path).map_err(|e| e.to_string())?;
Ok(OpenResult { path: path.display().to_string(), content })

// save_document（另存为分支）
let mut p = fp.into_path().map_err(|e| e.to_string())?;
if p.extension().is_none() {
    p.set_extension("md");
}

// import_image
let Some(src) = file else { return Err("cancelled".into()) };
let src = src.into_path().map_err(|e| e.to_string())?;
// ...后续 file_name() / fs::copy 直接使用 src
```

### 经验教训

- Tauri 2 dialog / fs 插件返回的路径统一是 `FilePath` 枚举，遇到"方法不存在/AsRef 不满足"的报错，优先调用 `into_path()` 或 `as_path()`。
- 弹窗取消返回 `None`（返回 `"cancelled"`），路径非法返回 `into_path()` 的 `Err`，两层都要处理。

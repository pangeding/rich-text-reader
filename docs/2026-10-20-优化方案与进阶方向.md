# 优化方案与进阶方向

> 日期：2026-10-20
> 项目：Tauri 2 + React 19 + TypeScript + TipTap 3 Markdown 编辑器
> 范围：现状审查、缺陷清单、体验/工程提升、进阶路线、第一步决策
> 状态：仅沉淀文档，未修改代码

## 1. 现状结论

MVP 闭环已经跑通：

- 打开 / 保存 / 另存为（Rust 端 `open_document`、`save_document`）
- TipTap 所见即所得编辑，Markdown 解析与序列化
- 图片选择后复制到文档旁 `assets/`，渲染时经 `convertFileSrc` 转 asset URL
- 工具栏格式化、链接弹窗、状态栏（脏状态 / 文件名 / 字数）

代码结构清晰，后端只有 3 个命令。当前问题**不在功能缺口**，而集中在：

1. 文案承诺了但未实现的快捷键；
2. 未保存内容缺少保护，存在丢稿风险；
3. 若干边界 bug（弹窗状态、图片覆盖、另存为路径）；
4. 缺少 lint / format / test / Makefile 等工程基建。

## 3. P1：体验与工程基建

### 3.1 工程化

- 缺少 lint / format / test：没有 ESLint、Prettier、Biome、Vitest 配置。
- `tsc` 只在 `build` 中执行，建议新增 `typecheck` 脚本。
- AGENTS.md 提到参考 `Makefile`，但仓库根目录**不存在 Makefile**，建议补 `Makefile` 或 `justfile` 统一常用命令。
- Rust 侧建议启用 `cargo fmt` / `cargo clippy` 并纳入检查。
- 建议补最小测试：
  - 前端：图片路径转换、LinkModal 状态、脏状态逻辑；
  - Rust：图片重名处理、原子保存、扩展名补全。

### 3.2 安全与健壮性

- `csp: null` 且 `assetProtocol.scope` 为 `["**"]`，权限过宽。建议设置 CSP，并把 scope 收敛到文档目录 / 用户目录。
- Rust 命令统一返回裸 `String` 错误，建议改为结构化错误类型，前端用 toast 区分「取消 / 失败 / 成功」。
- 图片相对路径缺少校验（`../` 逃逸），建议在 Rust 侧规范化并限制在文档目录内。
- 外部编辑检测：文件被其他程序修改/删除时无感知，可引入 `notify` 监听。

### 3.3 交互细节

- 窗口标题固定为「Markdown 编辑器」，不显示文件名与 `*` 脏标记。
- 状态提示只有单条 banner，且点击关闭后无历史记录。
- 不支持拖拽 `.md` 进窗口打开、不支持粘贴/拖入图片。
- 工具栏 emoji 与文字图标混排（🔗 🖼），建议统一图标风格，并补充 `aria-label` / `aria-pressed`。
- 快捷键逻辑应抽成 hook（`useHotkeys`）或交给原生菜单，避免散落。

## 6. 第一步决策

**第一步：先做「数据安全闭环」，即 P0-2 未保存保护。**

理由：

1. 丢稿是当前最高风险，且用户操作路径最短（打开/关闭窗口即触发）。
2. 该改动会引入 `onCloseRequested` 与确认对话框，为后续快捷键、原生菜单、自动保存打下事件基础。
3. 不涉及编辑器内核与大范围重构，风险可控、可快速验收。

第一步的具体范围（按顺序）：

1. 关闭窗口时：若 `dirty`，弹出「保存 / 不保存 / 取消」。
2. 打开文件前：若 `dirty`，同样确认，避免静默覆盖当前内容。
3. 选择「保存」且当前无路径时，走「另存为」流程；取消保存则中止关闭。
4. 复用现有的 `save_document`，不新增后端命令（除非确认对话框需要）。
5. 补充最小验证：手动场景 + 后续可加 e2e。

验收标准：

- 有未保存修改时关闭窗口，必定出现确认；
- 选择「取消」后窗口保持、内容不丢；
- 选择「不保存」后正常退出；
- 选择「保存」后文件落盘再退出；
- 无修改时关闭不打扰用户。

下一步（第二步）：在第一步的事件基础上实现 P0-1 快捷键 / 原生菜单，再处理原子保存与图片去重。

# Windows 启动指南

> 日期：2026-10-20
> 环境：Windows 11 + Node.js 24 + pnpm 12 + Rust 1.99 + VS 2022 Build Tools

## 1. 环境要求

| 依赖 | 版本 | 检查命令 |
|---|---|---|
| Node.js | ≥ 22 | `node -v` |
| pnpm | ≥ 12 | `pnpm -v` |
| Rust（MSVC 工具链） | stable-msvc | `rustc -V` |
| VS 2022 Build Tools | 含「使用 C++ 的桌面开发」 | 见 2.2 |
| WebView2 Runtime | 任意新版 | 见 2.3 |

## 2. 安装

### 2.1 Rust

下载 <https://win.rustup.rs/x86_64>，执行：

```powershell
.\rustup-init.exe -y --default-toolchain stable-msvc --profile default
```

官方源不稳定时使用镜像：

```powershell
$env:RUSTUP_DIST_SERVER = "https://rsproxy.cn"
$env:RUSTUP_UPDATE_ROOT = "https://rsproxy.cn/rustup"
rustup default stable-msvc
```

验证：

```powershell
rustc -V
cargo -V
```

### 2.2 VS 2022 Build Tools

1. 下载 <https://aka.ms/vs/17/release/vs_BuildTools.exe>
2. 勾选「使用 C++ 的桌面开发」，其余默认
3. 安装后如提示重启，先重启

验证（有输出即就绪）：

```powershell
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property displayName
```

### 2.3 WebView2

```powershell
Test-Path "${env:ProgramFiles(x86)}\Microsoft\EdgeWebView\Application"
```

`False` 时安装：`winget install Microsoft.EdgeWebView2Runtime`。

### 2.4 pnpm 与项目依赖

```powershell
npm i -g pnpm
pnpm install
```

## 3. ERR_PNPM_IGNORED_BUILDS 解决方案

### 现象

```
Error: ERR_PNPM_IGNORED_BUILDS
  × installing dependencies
  ╰─▶ Ignored build scripts: esbuild@0.28.2
```

### 原因

- pnpm 12 默认 `strictDepBuilds: true`，未显式批准的依赖构建脚本会直接报错。
- pnpm 11 起**不再读取 `package.json` 中的 `pnpm` 字段**，`pnpm.onlyBuiltDependencies` 已失效。
- `onlyBuiltDependencies` 本身也已在 pnpm 11 被 `allowBuilds` 取代。

### 解决

在项目根目录创建 `pnpm-workspace.yaml`：

```yaml
allowBuilds:
  esbuild: true
```

并删除 `package.json` 中已失效的 `pnpm` 字段（否则会有警告）：

```json
"pnpm": {
  "onlyBuiltDependencies": ["esbuild"]
}
```

然后重新安装：

```powershell
pnpm install
```

> 也可执行 `pnpm approve-builds` 交互式批准，效果相同；`allowBuilds` 便于提交到仓库、团队统一。

## 4. 启动与打包

```powershell
# 开发模式（首次编译 Rust 依赖需 5–15 分钟）
pnpm tauri dev

# 仅调试前端（涉及 Rust 命令的功能不可用）
pnpm dev

# 打包，产物在 src-tauri/target/release/bundle/
pnpm tauri build
```

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| `cargo` / `rustc` 无法识别 | 重开终端，确认 `%USERPROFILE%\.cargo\bin` 在 PATH |
| `no active toolchain` | `rustup default stable-msvc` |
| `link.exe not found` | 缺 MSVC 组件，重装 VS Build Tools 的 C++ 工作负载 |
| 下载 Rust / crates 失败 | 使用 rsproxy 镜像（见 2.1、下方 cargo 配置） |
| `ERR_PNPM_IGNORED_BUILDS` | 见第 3 节 |
| `os error 4551` / 应用程序控制策略已阻止此文件 | 智能应用控制拦截，见 `2026-10-20-smart-app-control-阻止-rust-编译.md` |
| 窗口白屏 | 确认 `pnpm dev` 正常、WebView2 已安装 |
| 端口 1420 占用 | 结束旧 Vite 进程，或同步修改 `vite.config.ts` 与 `tauri.conf.json` 的 `devUrl` |

cargo 镜像（可选，`%USERPROFILE%\.cargo\config.toml`）：

```toml
[source.crates-io]
replace-with = "rsproxy-sparse"

[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"
```
